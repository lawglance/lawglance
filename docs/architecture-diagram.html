LawGlance — request path, today vs. after

What changes when the fixed LangChain chain becomes a LangGraph state machine sitting behind FastAPI. Same two boxes at the top of each column — the divergence starts at the service boundary.

NEW HOP

app.py no longer imports Lawglance directly — it becomes an HTTP client of api.py. That's the one edge every other change hangs off of.

CHAIN → GRAPH

chains.py's single LCEL chain, rebuilt every call, becomes agent.py's compiled StateGraph, built once. Retrieval becomes a named @tool; contextualize keeps today's "only reformulate when history exists" cost gate exactly.

BLOCKING → STREAMED

The client used to wait for the whole answer. Now it gets generate's tokens live over SSE, then one final event carrying the resolve_answer_citations()-checked citation list — same shape as today, just delivered incrementally.
